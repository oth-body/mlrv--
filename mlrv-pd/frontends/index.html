A Pure Data reimplementation
of mlrv2, now with frontends.

Three draft companion surfaces for a monome-grid-only live-sampling instrument. None of these are wired to the Pd patch — they're explorations of what an mlrv frontend could look like, built from the abstractions and patchers in mlrv-pd/.

How to run

Easiest: just open frontends/index.html directly in a browser (double-click, or xdg-open frontends/index.html). All four pages work over file:// — the patch-graph page has the .pd source files bundled inline.

Or, served over HTTP (so the patch graph reflects live edits to the .pd source without rebuilding):

cd mlrv-pd && python3 -m http.server 8765 --bind 127.0.0.1
# open http://127.0.0.1:8765/frontends/index.html

Full docs in frontends/README.md.

What these drafts are not

  • Not wired to the Pd patch. The Pd side remains grid-only — these are companion surfaces, not replacements.
  • Not a real audio engine. The sample loader's play button only simulates the file_poly message protocol; nothing makes sound in the browser.
  • Not a finished design. Surface archetypes here are Monitor (patch graph) and Operate (grid + loader) — the goal is to test layouts, not commit to a look.

What informed them

  • CLAUDE.md for the current state of the port (8 verified components, mixer not yet wired, tilt sensor not yet handled).
  • mapping.pd — confirmed: y=7 trigger row, slot = x, (7,0) = stopall.
  • file_poly.pd — confirmed: 8 slots × 4-voice round-robin polyphony.
  • master.pd — confirmed: tanh soft-clip, RMS meter in dB full-scale 100.
